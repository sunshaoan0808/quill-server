# 喂模型的上下文必须溯源到持久化存储

（吸收自 AIcove 架构宪法"DB raw message 是聊天上下文唯一真相源"，2026-10-11）

决定：任何组装 LLM 请求的调用点（回合引擎/导演/记忆抽取/审稿/蒸馏/主动关怀），其对话历史、角色状态、记忆内容必须能溯源到持久化存储（SQLite 表、`$KALEIDO_DATA` 下的 JSON/目录文件），禁止从 UI 投影、内存缓存累积态或前端回传历史重建。派生状态（摘要、向量、MVU stat_data）只允许作为"可从原始记录重建的缓存"存在，必须携带重建所需的锚点（消息 id / 原文哈希）。

理由：长会话连续性缺陷（宿醉系列审计的时间/天气/原著冲突）的常见根源就是上下文重建走了缓存或旁路；真相源唯一后，任何状态下重启/换端/回放都得到同一上下文。AIcove 以此为宪法条款并在 2000 条消息会话上验证了"基线+重放"模型可行（整链重放 321ms，缓存命中 23ms）。

执行：接线时逐调用点标注来源（PERSISTED/MIXED/MEMORY-ONLY/CLIENT-SENT），MIXED 以下视为待修；新增调用点 PR 必须声明来源。首轮审计见 `docs/plans/2026-10-11-truth-source-audit.md`。
